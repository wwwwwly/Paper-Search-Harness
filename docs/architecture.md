# 架构说明

Paper Search Harness 把模型的研究决策与执行约束分开。模型负责解释问题、选择工具、比较证据；运行时负责持久化、版本一致性、预算、取消和恢复。

## 模块边界

| 层 | 入口 | 职责 |
| --- | --- | --- |
| 领域 | `domain.py`、`research.py` | 研究对象、证据引用、约束判断和交付规则。 |
| 会话 | `session_service.py`、`run_lifecycle.py` | 输入幂等、执行预算段和合法状态转换。 |
| Harness | `harness/` | Agent Loop、异步协作、上下文、用量与恢复。 |
| 工具 | `tools/` | 类型化参数、执行日志、超时和 MCP 适配。 |
| 资料 | `retrieval/`、`documents/` | 发现、身份合并、来源读取、PDF 处理与索引。 |
| 基础设施 | `storage/`、`model_client.py` | SQLite、原始文件、检索索引与模型连接。 |
| 应用 | `api/`、`queries.py`、`frontend/` | 快照查询、HTTP/SSE 与交互工作台。 |

业务通过 `ports.py` 中的协议访问存储、模型、索引和来源。`bootstrap.py` 统一选择并组装实现。

## 一次研究请求

1. `SessionService.send` 在同一事务中保存用户消息、Run、Job 和事件，用 `client_id` 去重重试请求。
2. JobWorker 从持久化 outbox 投递任务，AgentRunner 加载已保存的状态与调用结果。
3. 主 Agent 更新 `TaskBrief`，确定问题、种子、必要条件、偏好和交付格式。
4. 检索返回候选；阅读工具保存原始来源与 `Evidence`。必要时，Deep 将独立工作交给 Worker。
5. `record_findings` 发布发现。只有主 Agent 可以更新正式 `PaperAssessment` 和研究问题的解决状态。
6. `submit_research` 校验版本、论文身份、条件与引用，接纳合法选择，将未知条件列为缺口。
7. 同一 `ResearchResult` 渲染为回答或报告，并形成有来源的研究记忆。

## 意图与版本

`TaskBrief` 是当前研究意图的业务来源。查询关键词、临时时间范围和来源选择属于检索策略，不自动变成用户条件。

| 版本 | 变化条件 |
| --- | --- |
| `input_revision` | 新用户输入。 |
| `basis_revision` | 目标、模式、种子、实验要求或必要条件改变。 |
| `task_revision` | Worker 分工追加指令或续接。 |
| `assessment_revision` | 主 Agent 更新某篇论文的判断。 |
| `result_revision` | 重新提交交付内容。 |

修改数量或输出格式可以保留同一研究依据下的判断；研究依据变化则使旧任务失效，原始来源仍然可用。模型调用前、判断保存时和结果发布前分别检查版本，减少用户纠正与异步结果之间的竞争。

## 证据与交付

`ResearchBoard` 聚合候选、问题、任务、发现、正式判断和当前结果。完整正文放在 Artifact/Source 存储中，不复制进 Board。

- 论文身份依赖 DOI、arXiv ID、规范 URL 或明确别名，不按近似标题自动合并。
- 搜索卡片用于发现，不能直接充当论文摘要证据。网页、摘要和 PDF 片段保留各自来源。
- RRF 只决定召回顺序。相关性使用 `direct / partial / background / irrelevant / unknown`，必要条件使用 `pass / fail / unknown`。
- 正式推荐必须身份确认、直接匹配、由主 Agent 采用且必要条件通过。数量不足可以交付部分结果。
- 机制比较要求候选与种子的双边引用；baseline 选择要求对用户明确的实验维度逐项说明可比性。

校验可以证明引用存在且属于对应论文，不能自动证明自然语言结论被原文蕴含。这是结构校验与语义判断的边界。

## 异步 Worker

ResearchCoordinator 管理根 Run 拥有的 `asyncio.Task`，最多三个 Worker 同时运行。Discovery Worker 负责独立分面的发现，Evidence Worker 负责已知论文的阅读与证据缺口。

任务创建后立即返回句柄；主 Agent 通过游标收取增量 Findings，也可以追加指令、续接或取消任务。依赖只能引用同根 Run 已存在的任务，创建顺序构成无环依赖。Worker 不递归委派，不正式提交研究结果；执行结束也不等同于研究问题已解决。

子任务使用独立上下文。主 Agent 读取发现和状态，不接收完整子对话。

## 预算、持久化与恢复

主 Agent 和 Worker 共用 RunMeter，使用绝对截止时间、收尾预留和 token 软目标。每次模型调用单独预留与结算，恢复时按持久化调用 ID 重建用量，避免重复汇总。缓存输入与 reasoning 是 token 明细，不再加到输入和输出总量上。

工具日志区分排队、执行、完成、已交还模型及结果不确定等状态。已完成结果可以复用；只有明确可重放的操作才允许自动重试。外部副作用无法保证 exactly-once，结果不确定时保留日志并交由用户确认。

PDF 下载、解析和索引记录已完成步骤，任务截止后保留已有文件；重新处理可以从保存的位置继续。根任务结束时回收所属 Worker 和未完成文档工作。

SQLite 事务保存业务状态与 outbox，独立投递队列负责执行调度。当前按任务类型各运行一个消费者，根研究跨会话串行；同一研究内部可并发。这个边界适合本地工作台，不代表分布式任务系统。

## 上下文、Skills 与记忆

ContextBuilder 从持久状态构建模型上下文：稳定规则、对话、按需 Skill、研究状态与预算。上下文压力升高时，先去除重复历史、缩短工具正文，再按需摘要；完整来源和实际模型请求仍保留供查看。

五个业务 Skill 分别覆盖主题检索、相关工作比较、baseline 选择、证据阅读和论文质量。每个 Run 保存加载过的正文及参考资料快照，恢复时继续使用该版本。

记忆分为明确偏好、研究结果和执行经验。自动召回最多四条研究/经验，正文软目标约 2k token；记忆提供研究线索，不能替代论文原始证据。索引任务检查记忆版本与删除状态，避免旧任务恢复已删除内容。

## 前端与可观测性

React 工作台先读取会话快照，再通过 SSE 接收增量事件。事件序号用于断线重连和去重；前端以动画帧合并更新。API 类型从 FastAPI OpenAPI 生成。

工作台可查看研究问题、Worker、工具结果、PDF 引用和模型 Trace。Trace 用于复原模型当时看到的输入与返回内容，不保证重新调用模型会产生相同输出。
