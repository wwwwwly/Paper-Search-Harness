# 从意图构造查询、覆盖方法路线、筛选与收敛

将用户问题拆成任务对象、能力、机制、场景和排除项。硬条件来自用户，查询假设不改写 Brief。用概念/机制/标题/定向来源查询，RRF 只用于召回。读 shortlist 后发布 direct/partial/background 等有证据的判断。覆盖重要问题即可停止，低收益分面换策略或留下缺口，不为数量凑论文。

下一步先明确缺口、预期收益与停止条件。使用 update_task、record_findings 和 submit_research 的当前版本语义。

具体例子按需读取 references/examples.md。
